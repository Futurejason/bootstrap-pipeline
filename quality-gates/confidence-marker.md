# 可信度标注规范

## 三档标注

| 标记 | 含义 | 来源类型 | 用户应该做什么 |
|------|------|---------|--------------|
| ✅ | 确定 | 官方文档/权威来源 | 可直接采用 |
| 🔶 | 高度可能 | 二手来源/共识 | 重要决策前抽查验证 |
| ⚠️ | 推测 | 经验/逻辑推断 | 必须验证后再采用 |

## 标注位置

### Skill 输出层面
每个 skill 的 output 整体标注一个可信度。

### 论断层面
每个关键论断单独标注（见 evidence-chain.md）。

### 交付物层面
deliver 的摘要标注整体可信度（取所有论断的最低档）。

## 自动降级规则

以下情况自动从 ✅ 降到 🔶：
- 数据 > 2 年
- 来源链接失效
- 仅有一个来源支持

从 🔶 降到 ⚠️：
- 多来源相互矛盾
- 基于强假设
- 用户场景与原始来源差异大

## 推测项的处理

每个 ⚠️ 必须配套：
1. 明确说"这是推测"
2. 列出推测依据
3. 给出验证方式（"建议先小规模测试"）

例：
```
【论断】此方案 6 个月可回本
【可信度】⚠️
【说明】基于过去 3 个相似项目的均值，但你的市场和团队条件不同
【验证建议】
  1. 前 30 天小规模投入，监测 CAC 与 LTV
  2. 如 CAC > 假设的 1.5 倍 → 暂停扩大投入
  3. 90 天复盘后再决定是否全面铺开
```

## 用户感知

### deliver 摘要中
```
## 整体可信度：🔶 高度可能

主要论断 60% 为 ✅，30% 为 🔶，10% 为 ⚠️。
建议：方案 A、B 部分（标 ✅）可直接采用；方案 C 部分需先验证。
```

### 反复出现 ⚠️ 时
- 在 review 阶段降低可行性评分
- 主动建议简化方案

## 不允许的情况

- ❌ 全程不标注
- ❌ 全部标 ✅（除非真的全是官方来源）
- ❌ 标注但不说理由
- ❌ 用户问"为什么是 ⚠️"答不出来
