# L2 标准级流程

## 适用场景

- 方案设计、文档撰写、行业咨询、数据分析
- 需要分析对比、有产出物
- 复杂度评分 3-5

## 流程

```
classify → clarify → resource → plan → execute → review → deliver
```

6 个阶段（不含 classify）。

## 用户介入点

- 🔵 P1：clarify 完成后（如有阻塞性不确定）
- 🔵 P2：plan 完成后（必触发）
- 🔴 P3：任意阶段阻塞时
- 🟢 P4：deliver 完成后

## 时间预估

- 短方案/文档：30 分钟 - 2 小时
- 中等咨询：半天 - 1 天
- 完整方案文档：2-3 天

## 关键流程节点

### resource 阶段
- 分析用户提供的资料
- 如果资料严重不足 → P3 阻塞决策

### plan 阶段
- 给出 2-3 个候选方案
- 必须 P2 用户选方案
- 用户拒绝所有方案 → 重新 plan（最多 2 次）

### review 阶段
- 不通过 → 回 execute（最多 3 次）
- 反复不通过 → DOWNGRADE 简化交付

## 示例：开咖啡店方案

```
用户：我想开一家咖啡店，给我个方案

[classify] domain=business, complexity=L2, expert=business-consultant

[clarify]
  - 复述：开咖啡店的可行性方案
  - P1 阻塞性问题：预算多少？地点偏好？
  - 等待用户回复

用户：30 万预算，福州市区

[clarify] DONE

[resource]
  - 已知约束：30 万预算、福州市区
  - 缺失：目标客群定位、是否加盟
  - 默认假设：年轻白领、独立运营

[plan]
  - 方案 A：精品独立咖啡店（预算 25 万，差异化）
  - 方案 B：连锁加盟（预算 30 万，省力）
  - 方案 C：移动咖啡车（预算 10 万，灵活）
  - 推荐 A
  - 🔵 P2 用户选择

用户：方案 A

[execute]
  - 选址建议
  - 资金预算明细
  - 装修方案
  - 菜单设计
  - 营销计划
  - 时间表

[review] 4 维评分通过

[deliver]
  - 完整方案文档
  - 🟢 P4 验收
```
