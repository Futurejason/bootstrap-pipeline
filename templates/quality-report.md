# 质量报告模板

## 使用场景

review skill 的标准输出格式。

## 标准结构

```markdown
# 质量评审报告

## 待评审产出

- 产出类型：[code / doc / plan / analysis / other]
- 来源 skill：[execute / plan / design / ...]
- 涉及内容：[简述]

## 四维评分

### 完备性（Completeness）：X/10

**通过线**：8 | **状态**：✅/⚠️/❌

检查清单：
- [ ] 用户原始问题的所有点都回答了？
- [ ] 边界场景考虑了？
- [ ] 失败处理路径有了？
- [ ] 必要的依赖、前置条件说明了？
- [ ] 关键约束都明确了？

打分依据：覆盖 N/M = X 分

不完备项：
1. [缺失 1]：[影响]
2. [缺失 2]：[影响]

### 准确性（Accuracy）：X/10

**通过线**：8 | **状态**：✅/⚠️/❌

检查清单：
- [ ] 关键论断有证据链？
- [ ] 数字/数据来源真实？
- [ ] 代码逻辑能跑通？
- [ ] 引用的文档/法规可查？
- [ ] 没有事实性错误？

不准确项：
1. [问题 1]：[修正建议]
2. ...

### 一致性（Consistency）：X/10

**通过线**：7 | **状态**：✅/⚠️/❌

检查清单：
- [ ] 与上游 skill 输出一致？
- [ ] 内部不矛盾？
- [ ] 术语统一？
- [ ] 风格统一？

不一致项：
1. [问题 1]
2. ...

### 可行性（Feasibility）：X/10

**通过线**：7 | **状态**：✅/⚠️/❌

检查清单：
- [ ] 在约束内可执行？
- [ ] 资源足够？
- [ ] 步骤具体可操作？
- [ ] 风险可控？

不可行项：
1. ...

## 综合判定

- ✅ PASSED：4 维都 ≥ 通过线
- ⚠️ PASSED_WITH_NOTES：任一维度差距 ≤ 2
- ❌ FAILED：任一维度差距 > 2

**当前判定**：[✅/⚠️/❌]

## 对抗性自检

### 用户视角发现
- [问题 1]：[严重度] | [建议]

### 对手视角发现
- ...

### 维护者视角发现
- ...

### 新手视角发现
- ...

### 极端场景发现
- ...

## 改进建议（按优先级）

### P0 必须修
- [改进 1]：[具体动作]
- [改进 2]：[具体动作]

### P1 建议修
- ...

### P2 可选
- ...

## 决策

- ✅ PASS → 进入 deliver
- ⚠️ PASS_WITH_NOTES → 进入 deliver，标注关注点
- ❌ RETRY → 回到上游 skill 重做
- ❌ DOWNGRADE → 切备选方案

## 记录

| 字段 | 值 |
|------|-----|
| 评审时间 | ... |
| 评审 skill | review v1.0.0 |
| 上游 skill | execute |
| 通过线 | 默认 |
```

## 关键要求

### 评分必须有依据
不能直接给 8 分，必须列出检查清单的具体项目。

### 不及格项要详细
每个不达标的维度，必须列出具体哪些项不达标。

### 对抗性自检至少 3 条
不能少于 3 条挑刺意见。

### 改进建议要可执行
不能写"提升质量"这种空话。要写"在 X 文件 Y 处加上 Z"。

### 决策清晰
明确告诉 orchestrator 下一步：PASS / RETRY / DOWNGRADE。
