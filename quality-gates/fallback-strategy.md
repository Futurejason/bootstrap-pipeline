# 失败降级策略

## 三层降级机制

```
正常执行
   ↓ 失败
重试（最多 3 次）
   ↓ 仍失败
切备选方案
   ↓ 备选耗尽
简化降级 + 上报
   ↓
DONE_WITH_CONCERNS / BLOCKED
```

## 第一层：重试

### 触发
- 单步执行失败
- review 评分不通过

### 策略
- 第 1 次：换思路重试（同方案不同实现）
- 第 2 次：暴露失败细节 + 调整参数 + 再试
- 第 3 次：仍失败 → 进入第二层

### 不做的事
- 不静默重试（用户应能看到尝试过程）
- 不无限重试（最多 3 次）
- 不在同样错误上重复（必须换方法）

## 第二层：切备选方案

### 触发
- 重试 3 次仍失败
- review 反复 FAILED

### 策略
1. 检查 plan 中是否有备选方案（B/C）
2. 如果有 → 切换到下一个方案 → 回到 plan/execute
3. 如果没有 → 进入第三层

### 用户介入
切备选时通知用户：
```
⚠️ 方案 A 执行失败 3 次，主要原因：[X]
准备切换到方案 B（备选），预计影响：[范围]

是否继续？
- 继续 → 切换执行
- 重新规划 → 回到 plan
- 放弃 → 终止
```

## 第三层：简化降级

### 触发
- 备选方案耗尽
- 用户拒绝继续

### 策略
1. 列出已完成部分 + 未完成部分
2. 评估"最小可交付"边界
3. 简化交付：去掉失败部分，保留可用部分
4. 状态：DONE_WITH_CONCERNS

### 输出格式
```
## 降级交付说明

### 已完成（可用）
- 模块 A：✅
- 模块 B：✅

### 未完成（建议你后续处理）
- 模块 C：失败原因 [X]
  - 已尝试方法：[A/B/C]
  - 建议方向：[D]
  - 影响：[范围]

### 整体可用性
[评估当前交付物的可用程度]
```

## BLOCKED 状态处理

### 触发
- 缺关键信息无法继续（NEEDS_INPUT）
- 用户拒绝所有选项
- 工具/平台限制

### 处理
1. 状态：BLOCKED
2. 输出格式：
```
## BLOCKED — [简述]

### 卡点
[具体问题]

### 已尝试
- 方法 1：[失败原因]
- 方法 2：[失败原因]

### 需要你
- [ ] 提供 [X]
- [ ] 决定 [Y]
- [ ] 或：放宽某约束

恢复后，回复"继续"我会从这里恢复。
```

## 状态转移图

```
[STARTED]
   ↓
[执行中] ─→ 失败 → [重试 1] → [重试 2] → [重试 3]
   ↓                                          ↓
   ↓                                    [切备选方案]
   ↓                                          ↓
   ↓                                  [简化降级] / [BLOCKED]
   ↓
[PASSED] / [PASSED_WITH_NOTES] / [DONE_WITH_CONCERNS] / [BLOCKED]
```

## 不允许的失败处理

- ❌ 静默吞掉失败（"差不多就行了"）
- ❌ 假装成功
- ❌ 把失败转移给用户排查（"你检查一下日志"）
- ❌ 跳过质量门
- ❌ 无限循环重试
