# 进度报告模板

## 使用场景

execute skill 在长流程中（L3 多模块）按阶段汇报进度。

## 标准格式

```markdown
## 模块 [N] 完成

### 完成内容
- [具体输出 1]
- [具体输出 2]

### 与设计文档对应
- 对应模块：[design 中的模块名]
- 实现一致性：[完全一致 / 有偏差]
- 偏差说明：[如有偏差，说明原因]

### 验证结果
| 检查项 | 状态 | 说明 |
|--------|:----:|------|
| ... | ✅ | ... |
| ... | ✅ | ... |
| ... | ⚠️ | [警告原因] |

### 遇到的问题及处理
1. [问题 1]
   - 处理：[做了什么]
   - 结果：[是否解决]

### 用时
- 预估：[X 小时]
- 实际：[Y 小时]

✅ 模块 [N] 完成，准备进入模块 [N+1]
```

## 用户介入触发

模块完成后是否需要用户确认：
- L2 流程：通常不打断，连续执行
- L3 流程：每完成主要模块可询问"是否继续？"

询问格式：
```
🔵 模块 [N] 完成。预计模块 [N+1] 耗时 [X 小时]。
是否继续？（不响应默认继续）
```

## 进度可视化

L3 流程中输出整体进度：

```
进度：[████████░░] 80%

已完成：
- ✅ 模块 1：用户认证
- ✅ 模块 2：数据模型
- ✅ 模块 3：API 路由
- ✅ 模块 4：业务逻辑

进行中：
- 🟡 模块 5：测试用例

未开始：
- ⏳ 模块 6：部署
```

## 异常情况

### 发现与方案不符
立即汇报，不静默继续：

```
⚠️ 模块 X 执行中发现问题

预期：[方案中的描述]
实际：[发现的现象]
影响：[对后续的影响]

建议处理：
- 选项 A：[方案]
- 选项 B：[方案]

请决定（这是 P3 阻塞决策）。
```

### 单步失败
按 fallback-strategy.md 处理：
- 第 1 次失败：重试
- 第 2 次失败：换思路
- 第 3 次失败：切备选方案 + 上报
